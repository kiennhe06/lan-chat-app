Vai trò
Bạn là kỹ sư phần mềm chuyên nghiệp, có kinh nghiệm xây dựng ứng dụng desktop Electron + Node.js. Viết code production-ready, comment tiếng Việt, tuân thủ kiến trúc phân lớp.

Nhiệm vụ
Viết 2 codebase độc lập cho một hệ thống LAN Chat:

server/ — Node.js project thuần, chạy node index.js, không Electron, không UI. Đóng gói dạng folder (zip), copy sang máy Server, chạy trực tiếp bằng Node.

client/ (tên folder lan-chat-app/) — Electron app, đóng gói .exe portable, chạy trên mọi máy (kể cả máy Server).

Hai bên giao tiếp qua WebSocket. Client có thêm khả năng P2P mesh để chat khi server offline.

1.3. Build-time vs Runtime
Build-time (máy có internet):

Server: cd server && npm ci → không cần electron-rebuild (build cho Node ABI sẵn) → zip folder server/ (bao gồm node_modules/ và portable Node).

Client: cd lan-chat-app && npm ci && npm run electron:rebuild && npm run build:renderer && npx electron-builder --win portable.

Runtime (máy offline LAN):

Server: extract zip → chạy node index.js (dùng Node bundled hoặc Node cài sẵn).

Client: chạy .exe trực tiếp.

2.7. Mức 3 — Offline-first P2P
2.7.1. Peer discovery
UDP broadcast port 5003 mỗi 5s: {app_name, peer_port: 5002, user_id, display_name, server_online}.

Xóa peer nếu miss 3 lần (15s).

P2P WS server port 5002, chỉ accept IP cùng subnet.

Auth handshake p2p:hello với session_token verify được local.

2.7.2. Auth offline
Khi login online: server trả session_token (JWT-like hoặc random hex). Client lưu client.db settings, TTL 7 ngày.

Khi server offline: client dùng session_token cache để auth với peer. Hết hạn → phải chờ server online.

Không hỗ trợ login offline bằng password (bcrypt không tính được local mà không expose hash — quá nguy hiểm).

Không hỗ trợ đăng ký user mới offline.

Không hỗ trợ đổi password offline.

2.7.3. Chat 1-1 offline
A gõ → ghi client.db status='pending', sync_state='pending_peer'.

Check peer B online qua UDP list.

Có → WS tới B:5002, gửi p2p:message với vector_clock.

B insert local sync_state='peer_synced', ACK.

A update sync_state='pending_server', status='sent'.

B không online → giữ pending_peer, retry khi B xuất hiện.

2.7.4. Chat group offline
Gửi cho tất cả peer online.

Thiếu member → sync_state='partial_peer', không đánh dấu sent cho tới khi đủ hoặc server online.

Ghi p2p_receipts: {user_id: timestamp}.

2.7.5. Vector clock
Mỗi client giữ {user_id: counter}.

Gửi: tăng counter mình, gửi snapshot.

Nhận: merge max(local[i], received[i]).

Sort tin: (1) server_id nếu có → (2) causal before → (3) concurrent: (created_at_local, sender_id, client_message_id) tie-breaker.

2.7.6. Tạo/sửa nhóm offline
Tạo: conversation_id local temp-<uuid>, owner_id = mình. Khi server online → push → server trả id thật → update local + broadcast cho members.

Đổi tên: update local version++, sync_state='pending_server'. Khi server online push. Conflict → LWW theo (updated_at, user_id).

2.7.7. File P2P
Chunks 512KB qua WS binary frames.

B nhận → data/downloads-p2p/<hash>/ → verify SHA-256.

Khi server online → A upload file gốc lên server.

2.7.8. Sync reconciliation
Trigger khi WS tới server mở lại. Quy trình:

sync:status → số pending.

Batch message sync_state IN ('pending_server', 'peer_synced') → sync:message-batch → server upsert theo client_message_id → trả {server_id, status} → client update 'synced'.

Batch actions (conv_create, rename, member changes) qua action_queue.

Batch file P2P chưa upload.

Conflict 409 → default keep server, log warning.

Toast "Đã đồng bộ N tin, M file".

Progress UI: thanh nhỏ ở header, không block.

2.7.9. UI offline
Banner vàng: "⚠️ Server offline — Đang chat P2P. Tin sẽ tự đồng bộ khi server online."

Icon trạng thái:

pending_server: 📤 mờ.

pending_peer: ⏳.

partial_peer: 📤 + badge cảnh báo.

Progress sync: "Đồng bộ 15/50 tin...".

7. Database schema
7.1. Server DB (LANChat-Server/data/server.db)
Giống bản trước, không có client.db trong server folder. Bổ sung cho Mức 3:

sql
ALTER TABLE messages ADD COLUMN vector_clock TEXT;
ALTER TABLE conversations ADD COLUMN version INTEGER DEFAULT 1;
ALTER TABLE conversations ADD COLUMN client_temp_id TEXT;
7.2. Client DB (data/client.db cạnh .exe)
Giống bản trước, bổ sung cho Mức 3:

sql
ALTER TABLE messages ADD COLUMN vector_clock TEXT;
ALTER TABLE messages ADD COLUMN p2p_receipts TEXT;
ALTER TABLE messages ADD COLUMN created_at_local TEXT;

ALTER TABLE conversations_cache ADD COLUMN version INTEGER DEFAULT 1;
ALTER TABLE conversations_cache ADD COLUMN sync_state TEXT DEFAULT 'synced';
ALTER TABLE conversations_cache ADD COLUMN client_temp_id TEXT;

CREATE TABLE IF NOT EXISTS peers_cache (
  user_id INTEGER PRIMARY KEY, display_name TEXT, last_ip TEXT, last_port INTEGER,
  last_seen TEXT, server_online INTEGER DEFAULT 0, session_token TEXT
);
CREATE TABLE IF NOT EXISTS vector_clock (user_id INTEGER PRIMARY KEY, counter INTEGER DEFAULT 0);
CREATE TABLE IF NOT EXISTS action_queue (
  id INTEGER PRIMARY KEY AUTOINCREMENT, action_type TEXT NOT NULL, payload TEXT NOT NULL,
  vector_clock TEXT, created_at TEXT NOT NULL, retry_count INTEGER DEFAULT 0, last_error TEXT
);
CREATE TABLE IF NOT EXISTS p2p_files (
  file_hash TEXT PRIMARY KEY, local_path TEXT NOT NULL, file_size INTEGER, mime_type TEXT,
  received_from_user_id INTEGER, received_at TEXT, uploaded_to_server INTEGER DEFAULT 0
);
8. WebSocket events
Auth: register/ok/err, login/ok/err, reconnect, disconnect, user:created.

Messages: send, new, edit/edited, recall/recalled, status_update, read, pin, unpin.

Conversations: created, updated, deleted, rename, addMember(+Result), approveMember, rejectMember, removeMember, setAdmin, delete, requestPending, pendingList, memberPending, pinned, unpinned.

Sync: request, response, ack, status, message-batch(-ack), action-batch(-ack), file-batch.

P2P: hello, hello-ack, message(-ack), message-edit, message-recall, file-start, file-chunk, file-complete, file-ack, typing, presence.

Presence/typing: presence, typing.

WebRTC (tạm tắt): call:offer/answer/ice-candidate/end.

Logging: log:event, log:batch, log:ack, log:query, log:query:result.

Admin: listBlocked, blockIp, unblockIp, blockedList, blockIpResult, unblockIpResult.

Tất cả import từ shared/wsEvents.js — không gõ chuỗi trực tiếp.

9. Chất lượng mã
Comment tiếng Việt cho logic phức tạp.

JSDoc cho public API.

try/catch mọi I/O/network/DB.

Idempotent sync: client_message_id, log_id, vector_clock.

Không lưu file SQLite (không blob).

Không copy file vào thư mục app khi gửi.

Backup data/attachments/ định kỳ (README).

Không CDN, không analytics, không auto-update.

Test trên máy offline thật — checklist README.

UI hiển thị history không phụ thuộc server.

Body style cleanup: mọi effect set document.body.style phải có cleanup + reset trên unmount (tránh stuck input khi logout).

Không native confirm()/alert() cho interactive — dùng custom ConfirmModal hoặc window.api.dialog (native chỉ cho alert đơn giản).

Message status icon ngoài bong bóng (dùng msg-content-wrapper), nút 3 chấm căn giữa.

Reply quote 2 dòng + ellipsis.

Chỉ tiến state: sent → delivered → read.
